# 产品化计划：XkScreen（驱动 + 可视化软件 一体化安装包）

（2026-10-13 定稿；机主要求：每格 2 位数字、全部板块可自定义、一体化安装包、
前端可用 Next.js、尽量降低内存/资源占用）

## 目标

把"实验性驱动 + 文本文件配置"升级为一体化 Windows 产品：
**一个安装包 = 屏幕驱动服务 + 可视化配置软件 + 开机自启 + 卸载器。**

## 硬约束

- 屏幕每个数字格最多 **2 位数字（0-99）**，超出截断（数据目录见 RE-NOTES §8）
- CPUID 硬件数据层需要管理员权限（官方 SDK 同款，无法绕开）
- 官方软件可共存：安装时自动把官方服务 `SystemTemperatureMonitoring` 设为手动
- 屏幕刷新最高 ~300ms 一次（屏幕本身无掉电保持）

## 架构

```
[服务]  XkScreen.Service.exe      .NET Framework 4.8（唯一工具链）
          - 加载官方 XKWLib.dll（反射链，与现 PS 驱动一致）
          - 独占驱动屏幕：每 300/500/1000ms 一帧（可配置）
          - 配置：%ProgramData%\XkScreen\config.json（四个数字位 + 时钟）
          - 本地控制：命名管道（供 GUI / 安装脚本）
          - 自启：Windows 服务（LocalSystem）
[界面]  XkScreen.Gui.exe           WPF + WebView2（net8-windows）
          - 前端 Next.js 静态导出（HTML/JS 内嵌，不跑 Node 服务器）
          - 功能：4 个数字位下拉选择（实时预览）+ 时钟设置 + 服务状态/启停
          - 复用系统 WebView2 运行时；界面关闭后零常驻
[安装]  Inno Setup 一体化
          - 服务 + 界面 + 卸载器 + 开机自启注册 + 官方服务降级
```

## 技术选型结论

- 桌面壳：**.NET + WebView2**（对比 Tauri：本机无 Rust 工具链、产品 100% Windows、
  驱动服务已是 .NET；两者运行时内存主要由 WebView2 决定，壳本身仅差几十 MB）
- 前端：**Next.js 静态导出**（`output: 'export'`），不用 Node 服务器模式
- 驱动重写：**PowerShell → C#**（宿主内存 100MB+ → 预计 30-60MB）

## 内存/资源预算

| 组件 | 目标 |
|---|---|
| 服务（常驻） | ≤ 60MB |
| 采集刷新 | 沿用 CPUID SDK（官方同款，1s） |
| 屏幕帧 | 默认 500ms（CPU 占用约为 300ms 的一半） |
| 界面（按需打开） | 关闭后无残留进程 |

    关闭行为持久化到 `%ProgramData%\XkScreen\gui.json`
  - **GPU 风扇数据 + 传感器初始化加固**（2026-10-13）：
    根因 1：厂商 SDK 的硬件初始化是**懒加载在发送线程的重试循环里**（`thread_thread` 中
    `if (!hardware.InitState && !hardware.Start()) { sleep; continue; }`），而
    `XKWLibHelp.Start()` 里的一次性 `hardware.Start()` 首次必然失败——上次修复「周期性亮屏」
    时把 `thread_flag` 置 false，把该重试循环一并杀掉，初始化成败变成毫秒级竞态（服务有时有数据、
    有时全空）。修复：改由驱动自身**同步确定性初始化**（停止发送线程 → 重试 `hardware.Start()`
    至 `InitState=true` → 重新武装 `OpenRefresh(1000)` 刷新线程 → 20 秒内验证数据流并写日志）。
    根因 2：CPUID SDK 的 `Init2` 需要加载内核驱动（实测 `Driver error 5 = 拒绝访问`），
    **服务必须以管理员/SYSTEM 运行**（计划任务即为 SYSTEM）；非提权启动时 `/status` 返回
    `sensors_active:false`，控制台显示警示横幅，重启脚本改为提权部署（一次 UAC）。
    根因 3：GPU 风扇在本平台无任何厂商数据源（GPU 字典无 `fan` 键、SDK 的
    `GetDisplayAdapterFanSpeed` 返回 -1、NVML RPM 接口 rc=25 不支持），改用 **NVML 百分比**
    （`nvml.dll` 随显卡驱动分发）：实测与 `nvidia-smi` 完全一致（40% == 40%），零风扇停转时为 0。
    UI：`gpu_fan` 标签改为「GPU 风扇（%）」
  - **屏幕动画效果引擎**（2026-10-13）：新增 `Effects.cs` —— 屏幕只有数字值可控（颜色/亮度固件固定），

    分层设计：一次性特效叠加在持续效果之上，结束自动回落。自动触发：开屏时 / 倒计时归零时（none|steinsgate|boot）。
    配置新增 `effect` / `effect_target` / `effect_speed_ms` / `effect_on_screen_on` / `effect_on_timer_end`；
    API 新增 `POST /effect`（name/target/duration_ms/speed_ms，支持 stop）；`/status` 增加效果状态字段。
    控制台新增「动画效果」面板（模式/区域/速度/一键播放/自动触发，双语）。
    实测（服务日志）：效果模式 40 次循环 5 秒 ≈ 125ms/帧（8 帧/秒），基线 24 秒；各持续效果 `show`

## 验收标准

1. 安装包一键安装后：屏幕 ≤1 分钟亮起并显示数据；重启后自动恢复
2. 界面里改任意数字位/时钟设置 ≤2 秒上屏
3. 服务常驻内存 ≤60MB；界面关闭后无残留（服务除外）
4. 卸载后：自启项清除、官方服务可恢复
